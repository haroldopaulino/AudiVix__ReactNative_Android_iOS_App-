# AudiVix React Native

**Owner:** Haroldo Paulino

React Native 0.82.1 TypeScript app with Android and iOS native project skeletons and offline audio/video downloads.

## Prerequisites

Node.js 20.19.4+, JDK 17, Android Studio and the Android SDK, and Xcode/CocoaPods on macOS for iOS. The Gradle wrapper scripts and binary are not bundled, so Android requires `gradle wrapper` with a local Gradle 8.14.3 installation, or copying a Gradle wrapper from a trusted compatible project. This environment could not access the npm registry to install dependencies or validate the builds.

## Install

`npm install`

On Android, generate the wrapper if needed: `cd android && gradle wrapper --gradle-version 8.14.3 && cd ..`.

`npm run android`

On macOS, run `cd ios && bundle install && bundle exec pod install && cd ..` and open the Xcode workspace generated by CocoaPods. The project includes a minimal `ios/AudiVix.xcodeproj` that has not been validated in Xcode. You may need to reconcile native project settings with the matching React Native 0.82.1 template.

## Offline media

Enable Offline downloads in Settings, choose Download on a catalog entry, and open Offline to play saved files. Downloads use private document storage, resume is not supported, and in-progress downloads can be canceled. Removing a download removes the local file. Files are not automatically purged on sign-out. DRM-protected, HLS playlist, segmented streaming, or expiring-token links need server-side download support and are not handled by the single-file downloader. Storage usage counts against the device's app storage.

The API media key from the original project must not be treated as a secure credential embedded in a distributed client.

## Android autolinking setup

Install dependencies after unpacking the project, then confirm that the React Native CLI returns the Android package name before compiling:

```sh
npm install
npx react-native config
cd android
./gradlew clean assembleDebug
```

The `project.android.packageName` in the CLI output must be `com.audivix`. If Android was previously built from the older ZIP, clear `android/build/generated/autolinking/` before rerunning the build. The Gradle wrapper JAR and launcher scripts are generated using Gradle 8.14.3 if missing.


## Android package identity and autolinking

The Android namespace, application ID, Kotlin package declarations, Android manifest package, and React Native CLI configuration are all set to `com.audivix`.

From the project root, after `npm install`, run:

```bash
npx react-native config > react-native-config-output.json
node -e "const c=require('./react-native-config-output.json'); console.log(c.project?.android?.packageName); if(c.project?.android?.packageName!=='com.audivix')process.exit(1)"
```

The expected output is `com.audivix`. If it is not present, do not proceed to Gradle; inspect the CLI's output first.

Then run:

```bash
cd android
rm -rf build/generated/autolinking
./gradlew clean assembleDebug
```

## Android CLI platform detection

Run `npm install`, then `npm run check:android`. The check exits with an error if the CLI does not resolve `com.audivix`. Only after the check passes, run `cd android && ./gradlew clean assembleDebug`. This package adds explicit platform discovery hooks; it has not been verified by running a native Android build.

## Android autolinking fallback

The Gradle settings configuration now executes `scripts/autolink-config.js`, which preserves the React Native CLI dependency list and ensures the Android package identifier is `com.audivix`.

From the project root, run:

```sh
npm install
npm run check:android
cd android
./gradlew --stop
./gradlew clean assembleDebug
```

Do not run `./gradlew stop` without the two leading hyphens.

## Track Player Android Kotlin compatibility

`npm install` automatically applies a null-safe conversion in the installed `react-native-track-player` 4.1.2 Android source. The fix prevents the Kotlin `Bundle?` to `Bundle` compilation error in `MusicModule.kt`. Run `npm install` before building, including after reinstalling dependencies.

```bash
cd ~/Downloads/AudiVix_ReactNative
npm install
cd android
./gradlew --stop
./gradlew clean assembleDebug
```

The Gradle problems report in the supplied logs includes warnings about deprecated dependency APIs; those warnings are not the Kotlin compilation failure.

## Track Player patch-script repair

The postinstall script is now idempotent and does not fail `npm install` if it encounters a previously patched file or a source revision without matching nullable Bundle conversions. It applies the Kotlin null-safe conversion where the expected `Arguments.fromBundle(...originalItem)` pattern exists. A skipped patch does not guarantee Track Player will compile on your installed version.

After extracting, run `npm install`, then `cd android && ./gradlew clean assembleDebug`.


## Debug APK: red “Unable to load script” screen

The Android debug APK requires Metro to serve JavaScript. In the project root start `npm start`, keep that terminal open, and in a second terminal run `bash scripts/connect-debug-device.sh 3A131FDJG0040Y`. The script sets `adb reverse` for the selected device and restarts AudiVix. The phone must remain connected by USB for `adb reverse`, unless you configure a reachable wireless development server.

For an APK that runs without Metro, use a signed release build with the React Native JS bundle included. A normal debug APK does not provide a standalone distribution.

## Standalone Android release APK (local testing)

This release build packages the JavaScript code into the APK and does not require Metro.

The release configuration uses Android's development/debug signing identity for local device testing only. It is **not** suitable for Play Store distribution or production signing.

From the project root:

```bash
npm install
bash scripts/build-install-release.sh 3A131FDJG0040Y
```

Alternatively, build without installing:

```bash
cd android
./gradlew clean assembleRelease
```

The resulting APK is `android/app/build/outputs/apk/release/app-release.apk`.

If updating an installed app fails with `INSTALL_FAILED_UPDATE_INCOMPATIBLE`, the existing APK was signed with a different key. Uninstalling the old app will remove its local app data.

## React Native 0.82 Track Player startup compatibility

The `postinstall` script converts Track Player 4.1.x Android coroutine expression-body methods into `Unit`-returning functions. This avoids TurboModuleInteropUtils rejecting a `Job` return value at app startup.

Build and install the standalone test APK with `npm install` followed by `bash scripts/build-install-release.sh 3A131FDJG0040Y`. The Android release build and device launch still need validation.

## React Native 0.82 Track Player New Architecture runtime fix

The postinstall patch converts Track Player Kotlin coroutine methods to void-returning methods, fixes nullable Bundle conversion, and updates `MusicService` event emission to use the inherited `reactContext` rather than `reactNativeHost.reactInstanceManager.currentReactContext`. Re-run `npm install` before building to patch the installed dependency.

## React Native FS namespace compatibility

The dependency warning patch also ensures `react-native-fs/android/build.gradle` declares `namespace "com.rnfs"`. Android Gradle Plugin 8+ requires this namespace after the obsolete manifest `package` attribute is removed. The patch is idempotent and runs during `npm install`.


## Gradle version compatibility

Use Gradle 8.14.3. See `GRADLE_COMPATIBILITY.md`. Gradle 9.8.1 fails in the React Native included Gradle plugin due to Kotlin metadata mismatch in the provided terminal log.
